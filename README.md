## Что умеет

- Запускает Claude Desktop через ярлык **Claude VPN** только после проверки туннеля и TLS-соединения с `claude.ai`.
- Даёт уже открытому приложению **5–10 секунд** на восстановление VPN. По умолчанию — 10 секунд.
- Сбрасывает отсчёт, когда VPN восстанавливается.
- Поддерживает несколько VPN: **v2RayTun, MantaRay** и другие клиенты с распознаваемыми TUN/TAP-драйверами.
- Автоматически выбирает туннель по активному маршруту; имена адаптеров также можно задать вручную.
- Работает в трее, запускается при входе в Windows, ведёт локальный журнал без содержимого переписки.

> **Границы защиты.** Это контроль приложения, а не сетевой kill switch. Обычный ярлык Claude может ненадолго открыть процесс до его обнаружения. Во время допуска 5–10 секунд сетевой трафик не блокируется. Для запрета прямого трафика используй kill switch VPN или правила брандмауэра. Принудительное закрытие может привести к потере несохранённого ввода.

## Установка

1. Скачай `ClaudeVpnGuard-<версия>-windows.zip` на странице [Releases](https://github.com/MrFerrumL/claude-vpn-guard/releases/latest).
2. Распакуй архив и запусти `Install.cmd`.
3. Подключи VPN в режиме **TUN / полного туннеля**.
4. Открывай Claude через новый ярлык **Claude VPN** на рабочем столе или в меню «Пуск».

Нужны Windows 10/11 x64, .NET Framework 4.8 и установленный Claude Desktop из Microsoft Store. Python, отдельный .NET SDK и права администратора для утилиты не нужны. Самому VPN могут требоваться права администратора. Бинарник не подписан цифровым сертификатом; доступна самостоятельная сборка.

## v2RayTun и MantaRay

Не требуется привязка к одному клиенту. Программа ищет активный разрешённый адаптер, через который Windows направляет трафик к `1.1.1.1`, затем проверяет маршрут к IPv4-адресу `claude.ai` и устанавливает TLS-соединение через адрес этого адаптера.

По умолчанию разрешены имена `v2RayTun` и `MantaRay`. Автоопределение также распознаёт описания драйверов `sing-tun`, `Wintun`, `WireGuard`, `TAP-Windows` и `MantaRay`. Wi-Fi, Ethernet и VirtualBox сами по себе не считаются VPN. Это распознавание драйверов, а не подтверждение поставщика VPN.

В MantaRay нужен режим полного туннеля / TUN, создающий сетевой адаптер и маршруты. **Одного системного прокси недостаточно.** Если VPN использует другое имя или драйвер, добавь имя адаптера в настройках через `;`.

При переключении между клиентами проверяется новый туннель. Переключение должно уложиться в выбранный допуск; иначе Claude закроется. Автоматического повторного запуска Claude нет.

## Управление

Двойной щелчок по значку в трее — запуск Claude с проверкой. Правый щелчок открывает меню состояния, настроек, журнала и выхода. Значок может находиться под стрелкой **˄** возле часов.

| Параметр | По умолчанию |
| --- | --- |
| Имена адаптеров | `v2RayTun;MantaRay` |
| Автоопределение TUN/TAP | Включено |
| Допуск после потери VPN | 10 секунд; доступно 5–10 |
| Проверка адаптера и процессов | Каждые 250 мс |
| Проверка соединения | Следующая проверка через 1,5 с после завершения предыдущей |
| Журнал | `%LOCALAPPDATA%\ClaudeVpnGuard\guard.log` |
| Настройки | `%LOCALAPPDATA%\ClaudeVpnGuard\settings.xml` |

Если адаптер отключается, отсчёт начинается при ближайшей проверке. Если адаптер остаётся включённым, но сеть не работает, добавляется время обнаружения неполадки — обычно до 5 секунд. Длительный сбой DNS, интернета или TLS тоже считается отсутствием подтверждённого VPN.

Утилита должна оставаться запущенной. Выход из трея или завершение её процесса отключает контроль. Автозапуск действует после входа пользователя в Windows; это не системная служба.

## Сборка и проверка

В Windows PowerShell из папки проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Package.ps1
```

Используется штатный компилятор C# из .NET Framework. Внешних библиотек и загрузок во время сборки нет. Тесты проверяют политику запуска, таймер, восстановление и выбор адаптеров; они не отключают VPN и не закрывают приложения. CI собирает программу и запускает эти проверки на Windows.

Диагностика живого соединения, без закрытия приложений:

```powershell
Start-Process .\ClaudeVpnGuard.exe -ArgumentList '--diagnose', 'diagnostic.txt' -Wait
Get-Content .\diagnostic.txt -Encoding UTF8
```

Проверка на реальном v2RayTun выполнена. Поддержка MantaRay реализована через общий механизм маршрутов TUN/TAP; текущий статус ручной проверки указан в [журнале изменений](CHANGELOG.md). Тесты не дают гарантии отсутствия утечек трафика.

## Ограничения и приватность

- Отслеживается Claude Desktop; отдельно запущенный Claude Code не отслеживается.
- Проверка ориентирована на IPv4. Маршруты IPv6 самого Claude не контролируются.
- Правила выборочной маршрутизации внутри VPN не анализируются.
- Проверка устанавливает TCP/TLS-соединение с `claude.ai:443`. HTTP-запросы, переписка и авторизация не отправляются.
- Сертификат проверяется средствами Windows; онлайн-проверка отзыва сертификата в этой пробе отключена.
- В журнале: время, смена состояния, ошибки и PID закрытых процессов. Журнал ограничен примерно 1 МБ и остаётся на ПК.
- Конфигурации, подписки и ключи VPN не читаются. Телеметрии, сервера утилиты и автообновления нет.

## Удаление

Запусти `Remove.cmd` из архива или из `%LOCALAPPDATA%\ClaudeVpnGuard`. Будут удалены утилита, её журнал, настройки, автозапуск и ярлыки. Claude и VPN не удаляются.

## Участие

Для отчёта об ошибке укажи версию Windows, имя и описание VPN-адаптера, режим VPN и результат диагностики. Удали личные данные из журнала перед публикацией. Не публикуй подписки, токены и конфигурации VPN.
